OBIA for QGIS

Segment raster imagery, measure objects, and classify objects or pixels in the Processing Toolbox.

Plugin 0.1.1 · bundled OBIA 0.2.0 · experimental · QGIS 3.40–3.x / 4.x

Install and maintain the engine

  1. In QGIS, open Plugins → Manage and Install Plugins → Install from ZIP. Select obia_qgis-0.1.1.zip and enable OBIA.
  2. Open Plugins → OBIA → Set up OBIA and click Install engine. Allow the download and scientific validation to finish.
  3. Run Check OBIA dependencies from the Processing Toolbox. Open its HTML report in Processing → Results Viewer.

Setup supplies a private Python and scientific stack for Windows x64, Linux x64, and macOS Intel/Apple Silicon. It shows download size and required free space. It does not install into QGIS or alter other Python environments. Internet is required initially; installed engines process local data offline. All downloads are HTTPS and SHA256 verified.

Repair engine builds and tests a new installation before activating it. Failure or cancellation keeps the previous working engine. Remove engine removes only recognized engine generations; verified downloads remain cached. Your data and projects are separate.

Windows paths

The engine uses a short path outside your QGIS profile, normally %LOCALAPPDATA%\obia\e. Existing short directory names are used when available. Long profiles automatically fall back to %USERPROFILE%\.obia-e when that fits the audited package paths. No Windows long-path registry changes or administrator rights are required by setup.

Package paths are checked before any download. If an unusually long profile or network root still cannot fit, use QGIS Settings → Options → System → Environment to set OBIA_ENGINE_ROOT to a new, shorter folder you control, then restart QGIS. Do not create that folder yourself. Keep the override while using that engine. A failed unpacking cache is safely rebuilt on retry.

Metadata allows QGIS through 4.99 but does not certify every release/platform. See the repository's verification record before deployment. Windows/Linux ARM engine builds are not included. Restart QGIS after updating the plugin ZIP.

A simple object workflow

  1. Load a local, georeferenced raster. Clip it to a small study area first.
  2. Run SLIC segmentation. Save object polygons and optionally matching segment IDs.
  3. Run Extract object features when you need more than the initial band means, standard deviations, and counts.
  4. Create representative labelled points with a class field. Run Label objects from points and inspect conflicting objects.
  5. Run Classify objects with the full object layer, labelled training layer, and numeric predictor fields.

Bands: selectors use one-based QGIS band numbers. OBIA field names use zero-based positions: b0_mean is the mean of QGIS band 1. Statistics use source pixel values, not renderer colors.

SLIC segmentation

obia:slic produces polygons with unique segment_id values and selected-band mean, standard deviation, and valid-count fields. Set the approximate object count and compactness; larger compactness favors more regular shapes. Advanced settings include smoothing sigma in pixels and SLICO adaptive compactness.

All segmentation tools normalize selected bands independently to [0, 1], with RGB-to-Lab conversion disabled. An empty band selection means all bands. Optional masks must match the source grid; nonzero valid pixels are included. Source NoData and nonfinite selected-band values are excluded. The optional GeoTIFF contains the same segment IDs; zero is NoData.

Felzenszwalb segmentation

obia:felzenszwalb uses graph-based regions. Larger scale generally makes larger objects. Set smoothing sigma and minimum region size in pixels. Outputs and band/mask behavior match SLIC.

Quickshift segmentation

obia:quickshift uses mode-seeking regions. Kernel size, maximum distance, and the color-to-space ratio control grouping. Outputs and band/mask behavior match SLIC. Quickshift and Felzenszwalb operate on the prepared image, then clip results to the mask; pixels outside the mask can affect nearby segmentation boundaries.

Watershed segmentation

obia:watershed requires exactly one selected band. It floods low values in that surface first. Choose an approximate basin count and compactness. Use a precomputed gradient raster to segment imagery by its boundaries. An empty band selection only works when the input has one band.

Extract object features

obia:extractfeatures adds measurements to existing polygons, reprojecting them to the raster CRS. It replaces fields with the same names, preserves other attributes, and writes a new GeoPackage.

  • Statistics: mean, standard deviation, min/max, median, IQR, MAD, counts/fractions, variance, skewness, and kurtosis. Optional p10/p90.
  • NDVI: set both the near-infrared and red band fields; leave both empty to omit it. Summaries use per-pixel (NIR − red)/(NIR + red).
  • Shape: area, perimeter, axes, elongation, circularity, solidity, rectangularity, orientation, and hole count. Map units require a projected CRS; choose pixel units for geographic rasters. Area uses squared units.
  • Texture: enable GLCM texture for the selected bands. Distance is in pixels; gray levels range from 2 to 256 (default 32). Quantization bounds are fitted per band over the image and shared across objects. Tiny objects may have no valid pixel pairs.

Raster masks, NoData, and polygon holes are respected. Outside polygons and undefined measurements retain NULL values. Feature masks limit samples without changing the polygon's shape. Inspect missing values before training.

Label objects from points

obia:labelobjects assigns the chosen point class field to feature_class on each intersecting object. Points are reprojected to the object CRS. The main output contains only objects whose points agree on one class. Objects with conflicting classes are excluded and can be saved separately; unlabelled objects are excluded. Previous labels are reset. Points on boundaries can label more than one object; inspect their positions.

Classify objects

obia:classifyobjects fits Random Forest, Extra Trees, or XGBoost using selected numeric fields present in both the training and prediction layers. Exclude IDs, labels, grouping fields, and prior predictions. Output adds predicted_class and prediction_margin. The margin is the gap between the top two probabilities, not an accuracy estimate.

Choose the number of trees and holdout fraction. Advanced settings include maximum depth and random seed. A depth of zero means unlimited for Random Forest/Extra Trees and depth 6 for XGBoost. Computation uses one estimator thread per job.

Validation

Optionally supply Labelled test objects. The model then uses all training data, and the HTML report evaluates only the supplied test objects. Holdout settings are ignored. Test objects must have the selected numeric predictor fields. Set Test class field if its name differs from the training class field; leave it empty to use the same field name. Test classes must occur in training, but a test set may contain a subset of the classes. Training and test objects must be distinct.

Without test data, the default reserves 20% of samples with a stratified random split. Set the fraction to 0 to train on all samples without held-out accuracy. Advanced grouped validation keeps each site/group together; select its group field. Spatial validation holds out square blocks in projected CRS units. The optional buffer excludes training geometries near test geometries (whole groups/blocks when applicable). Every class must remain in training; small or poorly distributed datasets can fail this requirement.

For holdout validation, the HTML report describes holdout predictions only. OBIA does not refit on held-out samples afterward. Random splits may overstate performance for neighboring samples; choose grouped/spatial validation to assess transfer to new areas.

Classify pixels

obia:classifypixels learns from pixels containing labelled points and predicts every valid pixel using the selected bands. Points are reprojected to the raster CRS. Outside/NoData points and conflicting labels in a single pixel stop processing; matching duplicates count once. The same model and validation choices are available as for objects.

Optional Labelled test points are sampled from the same raster, using the same bands and mask. They must select different pixels from the training points. With test points, all training pixels fit the model and only the supplied test pixels are evaluated. Duplicate points within each set count once per pixel. Without test points, the current holdout settings apply.

The output preserves the raster CRS, dimensions, and transform. NoData is 0; class codes are 1..K, which may differ from numeric input labels. Read the mapping in the HTML report or GeoTIFF class_mapping tag before styling.

Check OBIA dependencies

obia:checkdependencies checks installed-engine status and runs a small real segmentation → features → labels → classification workflow, including XGBoost and raster/vector writes. It returns an HTML report and a READY boolean, so an unavailable engine can still produce a useful report. Use Set up OBIA → Repair engine if validation fails.

Inputs, memory, and outputs

Use local raster files with a saved CRS. Export web layers and subdatasets to GeoTIFF first. Apply band scale/offset metadata to actual values before processing. Raster renderer changes, the map view, and the project CRS do not change analysis inputs.

Vectors honor Processing's selected-features option, filters, and pending edits. Supply valid polygons or single points with a CRS. Existing segment IDs must be unique and non-null; missing IDs are generated. Raster masks must already be aligned to the source grid.

Full raster data and outputs occupy memory. Prediction batching does not make the workflow out-of-core. Clip large images first. Use QGIS for clipping, reprojection, mosaicking, rasterization, and styling.

Choose distinct output paths separate from all inputs. Vector outputs are GeoPackages, rasters are GeoTIFFs, and reports are HTML. Each completed file is staged before replacement. Canceling a multi-output job can retain a completed file or a hidden staging file.

Point clouds, optional deep-learning detection, SHAP, cross-validation UI, and serialized model persistence are outside this plugin.
